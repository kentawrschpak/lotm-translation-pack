## 2. СТЕПЕНИ ОПАСНОСТИ И ТОЧНОСТИ ГАДАНИЯ (Маятник и др. методы)
*(Стандартизация формулировок Клейна при интерпретации, дополнено методами из Томов 2 и 3)*

| Метод / Движение маятника | Интерпретация Клейна | Пример запроса / Ограничения | Новые методы (Том 2 и 3) |
| :--- | :--- | :--- | :--- |
| **По часовой стрелке** (широкий, ровный круг) | Да. Высокая степень уверенности. Положительный ответ. | «Это место безопасно для входа?» → Широкое «ДА». | |
| **Против часовой стрелки** (широкий, ровный круг) | Нет. Высокая степень уверенности. Отрицательный ответ. | «Враг ждёт в засады за этой дверью?» → Широкое «НЕТ». | |
| **Колебания вдоль оси** (вперёд-назад) | Скорее да / положительная тенденция. Умеренная уверенность. | «Стоит ли мне принимать это зелье?» → Колебания «ДА». | |
| **Колебания поперёк оси** (влево-вправо) | Скорее нет / отрицательная тенденция. Умеренная уверенность. | «Это правильный путь к цели?» → Колебания «НЕТ». | |
| **Слабое, вялое движение** | Неопределённый ответ. Помехи, недостаток данных, плохо сформулирован вопрос. | «Связан ли Азик с этой организации?» → Слабое движение. | |
| **Бешеное, хаотичное вращение** | Опасность! Катастрофический риск. Вмешательство высших сил, вопрос запретен. | «Стоит ли открывать эту древнюю дверь?» → Бешеное вращение. **Прервать!** | |
| **Маятник не двигается** | Невозможность гадания. Вопрос вне компетенции, блокировка, нахождение над Серым туманом без запроса. | «Каково точное имя Бога?» → Без движения. | **Блокировка 0-08:** Гадание о делах, связанных с артефактом 0-08, может быть заблокировано или искажено (гл. 471). |
| **Гадание на местоположение (лозоходство)** | Активный метод поиска. Используется бумажный журавль или другой указатель. | Поиск местонахождения «Человекоподобной тени» (гл. 381). | **Ограничение:** Может быть менее точным на больших расстояниях или при противодействии. |
| **Гадание во сне (активное)** | Метод слежки и получения визуальных образов. Позволяет проникать в сны цели. | Слежка за Рафтером Пондом для раскрытия его связей (гл. 388). | **Опасность:** Риск быть обнаруженным защищёнными целями или столкнуться с контролем над снами (например, «Ночной Кошмар»). |
| **Гадание во сне (пассивное)** | Получение откровений и предупреждений через собственные сны. | Сон Аарона о серебряном змее и бумажном журавле (гл. 386, 388). | **Механика:** Связано с астральной проекцией и влиянием духовного мира. Может быть индуцировано артефактами или высшими силами. |
| **Общие ограничения (Том 2 и 3)** | Гадание показывает **результат**, но не процесс. Подвержено искажениям со стороны Потусторонних с защитными способностями. Пространство над Серым туманом может восполнять недостающую информацию для гадания. | Карта Чёрного Императора блокирует прорицания, направленные на владельца (гл. 377). | **Усиление:** Пространство над туманом улучшает точность и блокирует внешние помехи. **Новое (Том 3):** В духовной форме гадание может быть точнее, но опаснее из-за автономных сущностей. |
| **Проверка действий Кубика Вероятности** | **Метод:** Ритуальное сожжение пламени с вопросом к Сущности Вечной Ночи над Серым туманом. **Ответ:** Пламя вспыхивает (да) или тухнет (нет). | Клейн проверяет, является ли причиной его неудач Кубик Вероятности (гл. 606). | **Специализированный ритуал** для проверки влияния артефактов, связанных с удачей и судьбой. |

## 11. ПРОТОКОЛ РАБОТЫ СО СНОСКАМИ НА ЭТАПЕ 6 (ГЛУБИННЫЙ КОНТЕКСТ)

**Цель:** Стандартизировать обработку авторских/редакторских сносок (вида `* --- (ред. А.): ...`), обеспечив их консистентность с каноном, полезность для читателя и **их последующее корректное оформление в финальном HTML-формате.**

### 11.1. Рабочий процесс и форматы на Этапе 6
*   **Исходные данные:** Переводчик получает текст главы, в котором сноски могут быть представлены в сыром виде (например, `* --- (ред. А.): ...`) или уже размечены.
*   **Рабочий маркер в тексте:** Для целей анализа и составления отчёта **в основном тексте главы** при первом ключевом упоминании сущности ставится символ `*`.
*   **Рабочий формат списка:** Все сноски выносятся в **отдельный список для согласования** в формате: `* --- (ред. А.): [Текст сноски]`. *(В финальном HTML-формате маркеры будут заменены на символы ★, ★★ и т.д.)*
*   **Ключевое правило соответствия:** Количество символов `*` в тексте главы должно точно соответствовать количеству строк в этом рабочем списке.

### 11.2. Алгоритм обработки на Этапе 6
Для каждой главы Переводчик-исполнитель обязан:
1.  Выявить все исходные сноски.
2.  Для **каждой сноски** заполнить строку в **таблице-отчёте** (см. 11.5).
3.  На основе таблицы выполнить правки (сократить, объединить, уточнить, удалить):
    *   **Сократить:** Оставить только ключевую, неочевидную из текста информацию.
    *   **Объединить:** Если несколько сносок об одной сущности — создать одну общую.
    *   **Уточнить:** Исправить неточности по канону.
    *   **Удалить:** Если информация тривиальна и полностью раскрыта в основном тексте главы.
*   **Корректировка маркеров:** При удалении сноски из списка соответствующий символ `*` удаляется из текста главы.
4.  Сформировать итоговый рабочий список сносок в формате `* --- (ред. А.): ...` на основе столбца «Итоговый текст сноски».
5.  Предоставить Главному редактору: **а) очищенный текст главы с символами** *, **б) итоговый рабочий список сносок, в) заполненную таблицу-отчёт.**
(Это конец аналитической фазы этапа 6. После утверждения списка редактором начинается фаза интеграции.)

### 11.3. Финальная интеграция утверждённых сносок (заключительная часть Этапа 6)
После утверждения рабочего списка Переводчик-исполнитель выполняет финальное оформление **непосредственно в предоставленном тексте главы:**
1.  **В тексте:** На основе **утверждённого списка сносок** заменяет символы `*` в тексте на последовательные индексы в формате `<sup class="footnote-ref">★</sup>`, `<sup class="footnote-ref">★★</sup>`, `<sup class="footnote-ref">★★★</sup>` и т.д. **Порядок индексов (★, ★★, ★★★...) строго соответствует порядку сносок в утверждённом списке.**
2.  **В конце главы:** Размещает утверждённые сноски **в блоке `<div class="footnotes">`**, который должен находиться строго **после разделителя** `<div class="chapter-end"><hr></div>`. Каждая сноска оформляется как блок:
    ```html
      <div class="footnote-item">
        <span class="footnote-marker">★</span>
        <span class="footnote-text">Текст первой сноски. (ред. А.)</span>
      </div>
      <div class="footnote-item">
        <span class="footnote-marker">★★</span>
        <span class="footnote-text">Текст второй сноски. (ред. А.)</span>
      </div>
    ```
3.  **Вставка JavaScript:** После оформления блока сносок, **непосредственно перед закрывающим тегом `</body>`**, необходимо вставить JavaScript-скрипт выравнивания пирамиды из раздела 5.4 файла `RULES_TRANSLATOR_MASTER.html`. Скрипт обеспечивает динамическое выравнивание звёздочек и адаптивную ширину маркеров сносок.

*Как описано в `RULES_TRANSLATOR_MASTER.html` (Разделы 5.2 и 5.3).*

### 11.5. Формат таблицы-отчёта по сноскам главы
Отчёт создаётся **до** внесения правок в текст и служит документом для согласования. Его ключевая функция — обеспечить баланс между маркерами `*` в тексте и сносками.

| № | Гл. | Исходная сноска | Сущность | Действие | Причина / Обоснование | Итоговый текст сноски | Контекст с `*` в основном тексте |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | [№] | `* --- (ред. А.): ...` | [Сущность] | Сокращение / Объединение / Удаление | Ссылка на канон или логику текста. | `* --- (ред. А.): ...` (или **УДАЛЕНО**) | Конкретная фраза из текста главы с добавленным символом `*` после названия сущности. Для удалённых сносок — **НЕТ**. |
| ... | ... | ... | ... | ... | ... | ... | ... |
| **Итого по главе:** | | **Было:** X | **Объединено в:** Y | **Удалено:** Z | | **Осталось:** (X - Z) | **Маркеров `*` в тексте:** (X - Z) |

**Назначение столбцов:**
*   **№:** Порядковый номер сноски в главе.
*   **Гл.:** Номер главы.
*   **Исходная сноска:** Полный текст до редактирования.
*   **Сущность:** Ключевой объект/персонаж/концепт.
*   **Действие:** Категория произведённого изменения.
*   **Причина:** Краткое обоснование решения со ссылкой на файлы канона (`systems_guide_v1.md`, `10_historical_context.md`, `09_story_milestones.md`).
*   **Итоговый текст сноски:** Финальный вариант для вставки в главу. Если удалено — пометка **УДАЛЕНО**.
*   **Контекст с `*` в основном тексте:** Фрагмент основного текста, **куда будет добавлен символ `*`**. Это обеспечивает проверку соответствия: каждая оставшаяся сноска имеет маркер в тексте, а для удалённой — маркер не ставится.

### 11.6. Критерии для удаления сноски
Сноска подлежит удалению, если она:
*   Дублирует информацию, которая явно и полностью дана в основном тексте главы.
*   Содержит чисто служебные указания (напр., `ред. А.: сверь с главой...`).
*   Не добавляет ценности для понимания сюжета, мира или глубины конфликта в **данной главе**.
